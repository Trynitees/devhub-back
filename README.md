# DevHub — бэкенд

Серверная часть платформы для программистов и студентов: посты с лайками и комментариями, статьи с избранным и рекомендациями, автоматический сбор статей из RSS-лент, модерация постов администратором.

Бэкенд написан на **Java + Spring Boot** и отдаёт данные фронтенду в формате JSON по HTTP.

- Репозиторий фронтенда (React): https://github.com/nast1xqw/DevHub_front

## Технологии

Проект написан на Java 17 и собирается с помощью Maven (в репозитории есть `mvnw`, поэтому отдельно устанавливать Maven не нужно). В основе лежит фреймворк Spring Boot с модулями Web, Data JPA, Security и Validation. Данные хранятся в базе PostgreSQL, а работа с ней идёт через JPA и Hibernate: таблицы создаются автоматически по описанным в коде сущностям. Авторизация реализована средствами Spring Security на основе сессий (cookie `JSESSIONID`), пароли хранятся в виде хешей BCrypt. Для автоматического сбора статей используются библиотека Rome (чтение RSS-лент) и библиотека Jsoup (очистка HTML).

## Что нужно установить

1. **JDK 17** или новее (версия указана в `pom.xml`, параметр `java.version`).
2. **PostgreSQL** 14 или новее.
3. IntelliJ IDEA (по желанию): проект запускается и из терминала.

## Запуск

### 1. Получить код

```
git clone https://github.com/Trynitees/devhub-back.git
cd devhub-back
```

### 2. Создать базу данных

Запусти PostgreSQL (на macOS через Homebrew: `brew services start postgresql@16`), открой консоль `psql` и выполни:

```sql
CREATE USER devhub WITH PASSWORD 'devhub';
CREATE DATABASE devhub OWNER devhub;
```

Таблицы создавать вручную не нужно: приложение создаст их само при первом запуске.

### 3. Проверить настройки

Все настройки лежат в `src/main/resources/application.yaml`:

| Параметр | Значение по умолчанию | Назначение |
|---|---|---|
| `server.port` | `8000` | Порт сервера. Фронтенд обращается именно к нему |
| `spring.datasource.url` | `jdbc:postgresql://localhost:5432/devhub` | Адрес базы данных |
| `spring.datasource.username` | `${DB_USERNAME:devhub}` | Пользователь БД (берётся из переменной окружения `DB_USERNAME`, если она есть) |
| `spring.datasource.password` | `${DB_PASSWORD:devhub}` | Пароль БД (переменная `DB_PASSWORD`) |
| `app.upload-dir` | `uploads` | Папка для загруженных файлов (аватары, фото постов) |
| `app.parser.sources` | список RSS-лент | Источники для парсера статей |

Если у твоей базы другие имя пользователя или пароль, задай их переменными окружения, например:

```
DB_USERNAME=myuser DB_PASSWORD=mypassword ./mvnw spring-boot:run
```

### 4. Запустить

Из терминала:

```
./mvnw spring-boot:run
```

(на Windows: `mvnw.cmd spring-boot:run`)

Или в IntelliJ IDEA: открыть проект и запустить класс `DevhubApplication`.

В консоли должна появиться строка `Tomcat started on port 8000`.

### 5. Проверить, что всё работает

Открой в браузере `http://localhost:8000/api/posts/`. Должен прийти JSON вида:

```json
{"ok":true,"posts":[],"page":1,"size":10,"total":0,"total_pages":0}
```

### 6. Запустить вместе с фронтендом

Фронтенд лежит в отдельном репозитории. Его сервер разработки (Vite) работает на `http://localhost:5173` и перенаправляет все запросы `/api` и `/media` на `http://localhost:8000`, поэтому бэкенд должен быть запущен на порту 8000. Порядок:

1. Запустить бэкенд (шаги выше).
2. В папке фронтенда выполнить `npm install`, затем `npm run dev`.
3. Открыть `http://localhost:5173`.

## Как стать администратором

Роль администратора нужна для создания и редактирования статей, запуска парсера и модерации постов. Отдельной страницы для этого нет:

1. Зарегистрируйся на сайте обычным способом.
2. В `psql` выполни (подставь своё имя пользователя):
   ```sql
   UPDATE users SET staff = true WHERE username = 'ваше_имя';
   ```
3. Выйди с сайта и войди заново: роль записывается в сессию при входе.

## Сбор статей (парсер)

Администратор может запустить парсер кнопкой на странице администратора во фронтенде или запросом `POST /api/articles/parse/`. Парсер читает RSS-ленты из списка `app.parser.sources` в `application.yaml`, берёт до 10 свежих записей из каждой, очищает текст от лишней разметки и сохраняет новые статьи (повторы пропускаются по ссылке на оригинал). Каждая статья получает тег с названием источника. Чтобы добавить издание, достаточно дописать в конфиг блок:

```yaml
- name: Название
  url: https://адрес-rss-ленты
```

Если один из источников недоступен, остальные всё равно обрабатываются, причина выводится в консоль.

## Структура проекта

```
src/main/java/com/devhub/devhub/
├── DevhubApplication.java      точка входа
├── common/                     общие классы
│   ├── ApiException            ошибка с HTTP-статусом и полем
│   ├── ErrorResponse           формат ответа об ошибке
│   ├── GlobalExceptionHandler  превращает ошибки в JSON
│   ├── FileStorageService      сохранение загруженных файлов
│   └── HtmlCleaner             очистка HTML (защита от XSS)
├── config/
│   ├── SecurityConfig          правила доступа, шифрование паролей
│   └── WebConfig               раздача файлов по адресу /media/
├── user/                       пользователи, регистрация, вход, профиль
├── post/                       посты, теги, комментарии, лайки, модерация
└── article/                    статьи, избранное, рекомендации, парсер
```

Внутри каждого раздела одинаковые слои:

- **Controller** принимает HTTP-запрос и возвращает JSON;
- **Service** содержит бизнес-логику (проверки, правила);
- **Repository** выполняет запросы к базе данных;
- **Entity** описывает таблицу;
- **dto** описывает формат запросов и ответов.

## База данных

| Таблица | Назначение |
|---|---|
| `users` | пользователи (поле `staff` отмечает администратора) |
| `posts` | посты (статус: `PENDING`, `APPROVED`, `REJECTED`) |
| `post_comments` | комментарии к постам |
| `post_likes` | лайки (связь пост ↔ пользователь) |
| `tags` | теги (общие для постов и статей) |
| `post_tags` | связь пост ↔ тег |
| `articles` | статьи |
| `article_tags` | связь статья ↔ тег |
| `article_favorites` | избранные статьи пользователей |

## Основные адреса API

Все ответы имеют вид `{"ok": true, ...}`, ошибки приходят как `{"ok": false, "errors": {"поле": ["текст"]}}`.

### Пользователи

| Метод и адрес | Доступ | Описание |
|---|---|---|
| `GET /api/auth/csrf/` | все | совместимость с фронтендом |
| `POST /api/auth/register/` | все | регистрация (сразу выполняет вход) |
| `POST /api/auth/login/` | все | вход |
| `POST /api/auth/logout/` | все | выход |
| `GET /api/auth/me/` | все | текущий пользователь (или `null`) |
| `POST /api/profile/` | вошедший | обновление профиля и аватара (форма `multipart`) |

### Посты

| Метод и адрес | Доступ | Описание |
|---|---|---|
| `GET /api/posts/?page=1&size=10` | все | лента одобренных постов с пагинацией |
| `GET /api/posts/{id}/` | все | один пост (неодобренный виден только автору и админу) |
| `POST /api/posts/create/` | вошедший | создать пост (форма: `title`, `text`, `tags_input`, `photo`) |
| `DELETE /api/posts/{id}/delete/` | автор или админ | удалить пост |
| `POST /api/posts/{id}/like/` | вошедший | поставить или убрать лайк |
| `GET /api/posts/{id}/comments/` | все | комментарии |
| `POST /api/posts/{id}/comments/create/` | вошедший | добавить комментарий |
| `GET /api/posts/pending/` | админ | посты на проверке |
| `POST /api/posts/{id}/approve/` | админ | одобрить пост |
| `POST /api/posts/{id}/reject/` | админ | отклонить пост |

Пост обычного пользователя создаётся со статусом «на проверке» и попадает в ленту только после одобрения. Посты администратора публикуются сразу.

### Статьи

| Метод и адрес | Доступ | Описание |
|---|---|---|
| `GET /api/articles/?tag=&sort=&page=1&size=12` | все | список; `sort`: `newest`, `oldest`, `title` |
| `GET /api/articles/{id}/` | все | одна статья |
| `GET /api/articles/recommendations/` | все | рекомендации по тегам избранного (для гостя пусто) |
| `GET /api/articles/favorites/` | вошедший | избранные статьи |
| `POST /api/articles/{id}/favorite/` | вошедший | добавить в избранное или убрать |
| `POST /api/articles/create/` | админ | создать статью (JSON: `title`, `text`, `source_url`, `tags_input`) |
| `POST /api/articles/{id}/edit/` | админ | изменить статью |
| `DELETE /api/articles/{id}/delete/` | админ | удалить статью |
| `POST /api/articles/parse/` | админ | запустить парсер |

Загруженные файлы доступны по адресу `/media/...`.

## Возможные проблемы

| Симптом | Причина и решение |
|---|---|
| `Connection refused` при запуске | не запущен PostgreSQL |
| `password authentication failed` | пользователь или пароль БД не совпадают с настройками (см. шаг 2 и переменные `DB_USERNAME`, `DB_PASSWORD`) |
| `database "devhub" does not exist` | не создана база (шаг 2) |
| `Port 8000 was already in use` | порт занят другой программой, останови её |
| После перезапуска сервера сайт «разлогинил» | сессии хранятся в памяти сервера, нужно войти заново |
| Ошибка 403 при действиях администратора | у пользователя нет роли админа или после выдачи роли не выполнен повторный вход |

## Примечания

- Защита от подделки межсайтовых запросов (CSRF) отключена, потому что проект учебный, а фронтенд и бэкенд работают через общий прокси. В рабочей системе её включают.
- Загруженные файлы хранятся в папке `uploads/`, она исключена из Git.
